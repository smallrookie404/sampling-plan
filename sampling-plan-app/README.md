# 系统测点布局调查 · 采样计划软件

把《0.系统测点布局调查2025.12.19（6）.xlsx》升级为可独立运行的本地软件，完整保留原表的自动计算、下拉校验与错误提示功能，不再依赖脆弱的动态数组公式。

## 快速开始

1. 双击 **启动采样计划软件.bat**（或用浏览器打开 `index.html`）；
2. 在「测点布局调查」页录入现场调查信息，右侧灰色列自动生成采样计划字段；
3. 完成录入后点「导出 Excel」，生成**只包含自动计算区（W~BI 共 39 列）**的交付文件；
4. 之后可用「导入 Excel」载入该导出文件，也可载入原表结构的完整文件继续编辑。

无需安装、无需联网、数据只保存在本机浏览器中（建议及时导出备份）。

> 通过「启动采样计划软件.bat」打开时，软件会自带本地服务，**数据记录保存为项目文件夹下的 `data\records.json` 文件**，可直接复制、备份；在「数据记录」页还可导出 JSON 备份。
> 若直接双击 `index.html` 打开（无服务），软件会进入“临时模式”，数据仅暂存浏览器并显示黄色提示条，正式使用请用启动脚本。

## 界面说明

- **测点布局调查**：主表。白色列为录入区（A~U），灰色列为自动计算区（W~BI，与原表列一一对应）；黄色列（岗位性质、接触类型、是否采样/测量、检测方式）可从下拉覆盖自动值，选择「（自动计算）」恢复；红框单元格表示校验错误，悬停可见原因。
- **危害因素库**：604 条危害因素字典，可搜索、新增、删除、修改，改动后主表自动重算；「恢复默认库」可还原内置数据。
- **检测项目参考**：444 个标准化检测项目名，支持搜索，重复项标红。
- 接害因素（D 列）输入时有联想提示，名称必须在危害因素库中可查，否则自动列标红提示。
- 常用操作：点击行号选中整行，用工具栏按钮新增 / 插入 / 复制 / 删除行。
- **录入区 Excel 式编辑**：点击单元格定位（高亮框为当前单元格），方向键移动光标，Enter 下移、Tab 右移（Shift 反向），F2 或双击进入编辑，直接输入替换原内容，Delete/Backspace 清空选中的内容、Esc 还原；Shift+方向键、Shift+点击或拖动扩展选择区域；Ctrl+C 复制、Ctrl+V 粘贴 Excel 表格内容（按行列对应填入录入区，超出区域自动新增行）；「清空录入区」可一键清除全部录入内容。
- 行操作支持**自定义行数**：新增 / 插入 / 复制 / 删除时可输入批量行数（1~1000）。
- **数据记录**：点「保存数据」为当前数据命名并保存到 `data\records.json`（项目文件夹内）；「数据记录」中可按名称或内容（车间 / 接害因素 / 检测项目）搜索，一键「调用」替换当前表格，减少重复输入；支持 JSON 备份导出与导入，同名记录导入时自动覆盖。
- **GitHub 配置**：部署到静态网页（GitHub Pages）时，在此填写仓库与 Token，保存的数据将通过 GitHub API 直接写入仓库中的 `data/records.json`，实现“数据库在 GitHub 上”。
- **GitHub 同步**：配置 GitHub 后（本地版或网页版均可），打开软件时自动从 GitHub 同步最新数据；「保存数据」直接写回 GitHub，本地文件仅作离线兜底；「数据记录」中可手动「从 GitHub 刷新」。

## 与原 Excel 的功能对应

| 原表功能 | 软件实现 |
| --- | --- |
| W~BI 动态数组公式 | `js/logic.js` 计算引擎，逐列对应原公式 |
| 下拉数据验证（是/否、定点/个体、班制等） | 录入区与可覆盖列的下拉选择 |
| 条件格式错误标红 | 错误单元格红框 + 状态栏错误计数 |
| 危害因素 / 检测项目两张参照表 | 独立页签，可维护、可搜索 |
| 外部引用“班制数”模板 | 已内化为代码逻辑，不再需要外部文件 |
| 导出 xlsx | 单张工作表，仅自动计算区（W~BI 39 列），供采样计划交付使用 |

计算规则与原表一致，包括：空白下填、默认值（固定 / 半手工作业 / 定点 / 否）、检测项目名称规范化、每班最大人数向上取整、班制组内回填、检测天数与每天样品数按危害类型判定、噪声源与危害来源自动判断等。

## 自动计算规则摘要

1. 单元/工作场所、岗位/工种、点位、人数、周天数、日接触时长等：空白自动继承上一行；
2. 岗位性质缺省「固定」，接触类型固定为「浓度（或强度）相对稳定」，作业方式缺省「半手工作业」，检测方式缺省「定点」，是否合岗缺省「否」；
3. 检测项目 = 接害因素经危害因素库规范为系统内名称；
4. 每班最大人数 = 岗位总人数 ÷ 班制数（五班=5、四班=4、三班=3、两班=2，含“其他”取其他班制数），向上取整；
5. 班制/班制数：同车间同岗位自动回填，缺省「单班 / 长白班」；
6. 是否采样/测量：手工值优先，否则危害因素库有“不检测原因”→否，否则是；
7. 检测天数：游离二氧化硅、噪声、高温、工频电场、手传振动、高频电磁场、紫外辐射、有机组分定性 → 1 天，其余沿用录入的检测天数；
8. 每天样品数：有机组分定性 / 个体采样 / 游离SiO₂ / 工频电场 / 高频电磁场 → 1；噪声 / 高温 / 手传振动 → 3；紫外辐射 → 1；日接触 0.5h→2、0.25h→1、其他→3；
9. 采样时间类型：定点→短时间、个体→长时间；
10. 噪声源：噪声且定点采样时，同车间同岗位存在个体噪声采样 → 是；
11. 危害因素来源：噪声 / 高温 / 紫外辐射 → 设备运行，否则原辅物料；
12. 备注列自动取回危害因素库中的“不检测原因说明”。

## 项目结构

```text
sampling-plan-app/
├─ index.html            入口页面
├─ server.mjs            本地服务（静态页面 + 数据文件读写，纯 Node 标准库）
├─ 启动采样计划软件.bat   一键启动（自动运行本地服务并打开软件）
├─ 停止采样计划软件.bat   停止本地服务
├─ data/records.json     数据记录文件（首次保存时自动生成）
├─ css/styles.css        界面样式
├─ js/
│  ├─ logic.js           计算与校验引擎（浏览器/Node 通用）
│  ├─ xlsxio.js          xlsx 导入导出（仅依赖内置 jszip）
│  ├─ data.js            内置危害因素库与检测项目（由原表提取）
│  ├─ jszip.min.js       第三方压缩库
│  └─ app.js             界面逻辑
├─ scripts/extract-data.mjs  从原 Excel 重新提取内置数据的脚本
└─ tests/                自动化测试（见下）
```

## 自动化测试

测试脚本基于 Node.js，验证“软件实现与原 Excel 结果一致”：

```bash
node tests/engine.test.mjs   # 引擎 vs 原表缓存结果（312 个单元格逐一对比）
node tests/xlsxio.test.mjs   # 导出文件可被 Excel 引擎打开 + 导入往返一致
node tests/ui.smoke.mjs      # 浏览器界面：计算、错误联动、覆盖联动、导出
```

已通过：引擎 312/312 单元格与原表一致；导出 xlsx 通过 OpenXML 校验并可被 Excel 引擎读取；浏览器往返导出/导入数据一致。

## 注意事项

- 浏览器建议使用新版 Chrome / Edge；IE 不支持。
- 静态网页部署下无法写本机文件夹，数据通过 GitHub API 保存；Token 仅保存在本机浏览器，请勿提交到仓库。
- 参考数据（危害因素、检测项目）来自原表；如需更新，可修改 `scripts/extract-data.mjs` 中的路径后重新运行（需 Node.js 与依赖）。
- 导出文件仅包含自动计算区；如需完整的原表三表结构，仍以原 Excel 为准。
